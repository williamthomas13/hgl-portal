## PL-498 — portal.highergroundlearning.com is canonical for the PUBLIC pages too; hgl.co becomes a pure redirector (Scarlett, Sep 23 — revises the Sep 21 domain-pair decision)

**Why (decision record, Scarlett Sep 23):** hgl.co has no domain history, so making it the canonical home of /classes, /team, /inquire and the school codes would split the brand across two domains for search engines and LLM entity resolution. The long-term plan (scoped for AFTER the Synap replacement) is to move the whole marketing site onto Vercel at the apex; in the meantime every public page should be canonical on a highergroundlearning.com host so no links or search history accrue to hgl.co that would have to be migrated twice. Printed codes keep working because hgl.co/{code} redirects.

**New pair:**
- `portal.highergroundlearning.com` — canonical for EVERYTHING the app serves: signed-in surfaces, emailed links, AND the public pages (/classes, /team, /inquire, /compass, /partner, /{code}, /{code}/register, /c/{slug}, the embeds). Sitemap, `<link rel=canonical>`, OG url, JSON-LD, llms.txt and the homepage-embed "More info" links all point here.
- `hgl.co` / `www.hgl.co` — 301 EVERY path to the same path + query on the portal host (`hgl.co/sls` → `https://portal.highergroundlearning.com/sls`), except the bare root, which keeps its existing 301 to the main site (PL-349, host-conditioned in `next.config.ts`), and the `[...forward]` behaviour for paths the portal doesn't own (unknown paths still 301 to `https://www.highergroundlearning.com/{path}` — the standing "hgl.co/sat → main-site /sat" rule). Nothing is ever *served* on hgl.co.
- `highergroundlearning.com` — Squarespace, untouched; its own /classes and /team pages become Squarespace URL mappings (301) to the portal host and the main-site menu items point there (Scarlett does this in Squarespace at cutover row 20).

**Code changes**
1. `proxy.ts`: on a `SHORT_PUBLIC_HOSTS` host, redirect **every** path (not only `isPortalOnlyPath`) to `https://${canonicalPortalHost()}${path}${search}` — 301 for public GETs (cacheable, passes link equity), 308 for anything else / non-GET so a POST is never downgraded. Keep the "never redirect the portal host" rule so there is no loop. The root `/` on hgl.co is still handled by the `next.config.ts` redirect (fires first) — assert both orders in the gate.
2. `publicSiteOrigin()` in `base-url.ts`: `PUBLIC_SHORT_ORIGIN` is retired (never set it); the function returns `emailBaseUrl()` (= `PRODUCTION_BASE_URL` = the portal host). Keep the function so its nine callers don't change; update its comment and the file header. If the env var IS set, ignore it and log once at boot (so a stale Vercel env can't resurrect hgl.co canonicals).
3. `[...forward]`: unchanged in behaviour but re-read it — with the proxy now redirecting all portal-owned paths away from hgl.co, `[...forward]` only ever sees hgl.co paths the app has no route for. Confirm it still 301s those to the main site and never to the portal host.
