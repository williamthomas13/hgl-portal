## PL-273 — Hourly sweep must not depend on GitHub Actions' best-effort scheduler (reported Aug 6, from a live outage)

2. **Self-monitoring**: when the sweep detects it's overdue (the dashboard already computes this), send an admin alert email (new AL template per standing rules) rather than relying on someone looking at the dashboard or on GitHub's notification emails. Fire on transition to overdue (not every hour it stays down), and note recovery in the next successful sweep's log line / activity feed.

Context notes: Scarlett's manual re-run (Aug 6, after the two failures) SUCCEEDED and cleared the backlog — confirming the failures were purely GitHub-side and recovery-by-rerun works; still verify the idempotency assumption formally and say so in the report. All portal data is TEST data.
