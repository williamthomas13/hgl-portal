## ✅ PL-347 — A real reporting period concept: month / quarter / year / all-time (Scarlett, Aug 14)
The PL-345 premise correction stands: nothing in the system has a time boundary — the report and snapshot are all-time. Scarlett wants a real period concept for reporting: monthly, quarterly, annually, etc.
**A. One period utility.** New `report-period.ts`: period kinds **This month · Last month · This quarter · This year · All time** (+ custom month-range via the existing month filter), all boundaries computed in America/Denver, each period carrying a plain-English label ("Q3 2026 · July–September") and its previous-period twin for deltas. ONE source — every reporting surface uses it; nobody re-derives boundaries.
**B. Report page.** A period selector joins the existing filters (replacing/absorbing the bare month dropdown — months become the custom option). All sections scope to it consistently: classes by class month, 1-on-1 by invoice period, packages by purchase month, revenue-by-service (PL-346) slices likewise — each section header states the period plainly. All-time remains the default until Scarlett says otherwise (it's what the page truthfully was).
**C. Snapshot card (PL-345).** The card gets the same period selector in miniature (persisted per-staff preference, e.g. `report_snapshot_period` — her chosen lens sticks); headline numbers + deltas computed vs the previous period twin ("↑ 3 vs last quarter"). Manager stripping unchanged.
**D. What this is NOT (scope fence).** A reporting lens ONLY — no schema "term" object, nothing about class scheduling/registration changes, no email copy changes. Quarters are calendar quarters unless Scarlett defines a fiscal/academic year — ASK before inventing an academic-term calendar.
**E. Parity.** Any period's numbers must equal the all-time numbers when the period is All time (mechanical check in regress:report, same spirit as the PL-333 parity gate).

**Shipped:** ONE new leaf `app/utils/report-period.ts` (zero imports — regress:report compiles it standalone next to term-report.ts): the five kinds + custom month-range resolve to inclusive Denver YYYY-MM bounds with plain-English labels ("Q3 2026 · July–September") and an equal-length previous-period twin; `monthInPeriod` is the ONE membership rule, and it's deliberately month-granular because every reporting row is already keyed by a Denver YYYY-MM (classes by class month, 1-on-1 by invoice month, packages by purchase month) — so scoping is a string comparison, zero new revenue math, and All-time parity is structural (unbounded admits everything incl. the honest 'unscheduled'/'unknown' buckets; bounded periods exclude them — a row that can't state its month can't claim membership in one). **Report page:** the period selector replaced the bare month dropdown (months live on as "Custom months" from/through selects offering every month any section knows); classes, 1-on-1, packages, and the PL-346 by-service slices all scope through the same resolved period, each header states it plainly, empty tables say "No paid invoices in {period}." instead of rendering blank, and the totals card becomes "Totals · {period}" (summed from the page's own period-scoped rows; school/class-type filters don't scope it, and it says so) — All time stays the default and renders byte-identically to before. **Snapshot card (PL-345):** mini selector (the five kinds; custom stays on the report page); any lens except All time renders periodFigures with plain-English deltas vs the previous twin ("↑ 5 vs Q2 2026", "even with" when flat, never a fake 0 when the twin is absent); All time renders the classic card unchanged.
