# DNS cutover — host-sensitive settings for the domain pair (PL-474, Sep 21 2026)

**Decision (Scarlett, Sep 21):** `portal.highergroundlearning.com` = every signed-in surface and every emailed link · `hgl.co` = the short public front (`/{code}`, `/{code}/register`, `/classes`, `/team`, `/inquire`, wildcard → main site). One deployment serves both. This table **replaces sections 2–4 of the DNS runbook** — Scarlett + Claude tick it through; Code touches none of it (no DNS, no Vercel domains, no env vars).

How the pair stays honest in code (shipped with PL-474): `proxy.ts` 308s signed-in / auth / tokenized paths from hgl.co to the same path + query on the portal host (`PORTAL_ONLY_PATH_PREFIXES` in `base-url.ts`); public routes on the portal host keep serving (never redirected back — no loop); canonical / OG / sitemap / JSON-LD / embed links use `publicSiteOrigin()` = `PUBLIC_SHORT_ORIGIN` once set; every emailed link uses `emailBaseUrl()` = `PRODUCTION_BASE_URL`; the origin guard treats `hgl.co` as production with or without `ADDITIONAL_PRODUCTION_HOSTS` (it is not a localhost / private / ngrok / `.vercel.app` host). Gate: `node scripts/regress-canonical-hosts.mjs http://localhost:3100`.
